# ADR-015: 统计过拟合反馈与探索修复


## 背景

实证表明：`ProfitGrowthStrategy` 在 2026 年 Q1 收益为 -5.48%、Q2 为 +20.09%，窗口间表现极不一致，却仍通过旧样本外（out-of-sample, OOS）合并门（`oos_sharpe=0.51`），反映策略拟合特定市场风格而非稳健 alpha。代码审查进一步揭示五处结构性断点：

1. OOS 评估仅读取跨折平均夏普比率，未利用 `fold_results` 衡量稳定性；
2. 合并门未实施多重检验校正（Bailey & López de Prado 所述经典情形）；
3. 失败信号未上行：被拒绝节点不写回 `backtest_result`，语言模型在反思阶段无法获知失败原因，只能进行无依据推断；
4. 选择阶段多样性逻辑失效：当 `max_select >= K` 且候选数充足时，仍可能全选同方向假设；
5. 前沿（frontier）语义错误：执行器将节点置为 VALIDATED 后前沿集合恒为空，「前沿控制」从未生效。

统计显著性是抑制过拟合的必要约束；在失败反馈与探索机制可观测、可修复之前，不宜单纯扩大搜索空间。门控工具的分层角色（硬性门控与诊断门控）在实现演进后由 ADR-022 按统计验证（statistical validation）实践重定；本文不再保留原 Tier S 正文。

## 决策

我们将过拟合治理拆为两层可独立实施的机制：

### Tier A：失败反馈闭环

被拒绝节点同样写回 `backtest_result` 与 `rejection_reason`；`_collect_tried_directions` 纳入 `dev_score`、失败原因与 `step_failures`，并递归收集子树信息；反向传播（backpropagate）提示模板显式提取失败原因，供语言模型进行针对性反思，而非无依据推断。

### Tier B：探索机制修复

`is_frontier()` 扩展为包含 VALIDATED 状态——已验证但尚未充分展开的叶节点仍属探索候选；选择逻辑改为严格集合语义，强制选取不同方向，候选不足时重新生成或降级为全选并记录警告。

原 Tier S「三道串行硬性门控、缺一不可」及其阈值约定已迁出至 ADR-022；本文不重复规定 Walk-Forward、DSR、PBO 的合并路径角色。

## 后果

**正面**

- 失败原因可上行，探索过程不再对被拒绝节点「失明」；
- 选择与前沿语义与假设树状态一致，减少无效重复探索。

**负面**

- Tier A/B 不直接提升合并统计门槛，过拟合抑制仍依赖 ADR-022 所规定的门控用法。

**中性**

- 调研结论明确不采用 UCB/MCTS 数值搜索（量化夏普噪声大、收敛不可靠），暂不实现 Arbor expand/prune 三动作与质量多样性（QD）行为描述符——均为后续可选决策，由 ADR-022 继承讨论。
