# ADR-017: 自我进化能力技能规格


## 背景

自我进化（self-evolution）优化的是任务执行过程而非策略本身，对策略质量的贡献属二阶效应且尚未充分验证。在统计门控与稳健基线尚未确立前，构建「自主修改提示模板、调参或反思架构」的能力存在自我腐化风险：无基线则无法判断调整是改善还是劣化。该能力体量大，宜自 ADR-016 拆出独立评审，并与 ADR-022 所规定的分期解锁对齐。

## 决策

在 ADR-022 对应档位解锁后，我们将补充以下四项技能。各项均全自主实现并启用，须具备版本追溯（versioned lineage）；不设置人工审批门槛，但所有变更可回溯、可回滚。未达对应档位不得启用相应能力。

### 技能 1：任务级经验回写与热启动（ADR-022 L1）

任务结束时通过 `reflect_and_record` 反思工具组合有效性，产出结构化 TaskExperience（字段含 `tools_used`、`outcome`、`lessons`、有效与无效模式，以及 `version` 与 `parent_sid` 谱系树）。新任务经 `hot_start` 检索相似经验并注入系统提示。

### 技能 2：进化元指标与报告（ADR-022 L0 起只读）

按日聚合策略研发成功率、耗时、失败模式排名、算子目录增长等指标；`report_evolution` 产出趋势报告，支持跨月对比。

### 技能 3：失败信号驱动自动反思（ADR-022 L2 调参面 / L3 改提示面）

双层检测：任务内同签名失败率，以及跨任务 `detect_stagnation`（连续无 OOS 改善、工具失败率超阈、耗时上升）。产出 AdjustmentProposal 物质。主智能体可自主执行的范围以 ADR-022 档位为准；未达 L3 禁止因停滞自动修改提示模板或放宽统计门阈值。

### 技能 4：提示模板自审计与修订（ADR-022 L3）

`audit_prompts` 扫描退役语法、字段表不一致、frontmatter 缺失、示例日期过时；`revise_prompt` 产出新版本文件（如 `foo_v2.md`，原文件保留，加载时取最高版本）。安全护栏：渲染验证、DSL 解析验证，以及元指标显示修订后失败率上升时自动回滚并标记为有害变更。

所有经验、指标、失败分析与调整提案统一存入 Substance（`form=KNOWLEDGE`，metadata 记录谱系：`version`、`parent_sid`、`signal_type`、`applied` 等）。

## 后果

**正面**

- 按档解锁后具备元认知能力：可提前发现提示契约问题、成功率下降与工具失败模式；相似任务经热启动可减少重复探索。

**负面**

- 进化工具增加主智能体工具总数，弱模型面临工具选择质量风险，须考虑工具分组或两级分发；全自主修订仍存在自我腐化与误判风险，版本追溯与自动回滚为必要但非充分保障；token 成本上升。

**中性**

- 解锁条件与禁止项以 ADR-022 为准，本文不重复列举。
